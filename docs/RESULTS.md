## 8. The ceiling, measured instead of assumed

No ceiling is hard-coded anywhere in the retrieval dynamics. The library is grown until precision falls below 0.90, and whatever size that happens at is reported. Averaged over 3 seeds per point — one seed is far too noisy to bisect on.

| Model width H | Measured T* | Saturated the search? |
|---|---|---|
| 16 | **18** | no |
| 32 | **18** | no |
| 64 | **72** | no |
| 128 | **147** | no |
| 256 | **612** | no |

Fitted on the 5 points that did not saturate: **T* = 0.302 · H^1.320** (r² = 0.938)

Implied quality-gap exponent **theta = +0.379** (`theta = 1/(2a)`).

Two honest caveats on that exponent.

1. The two narrowest widths both return 18, which is the floor: a library smaller than the number of variants cannot cover every kind of task, so the measurement is censored there and the exponent is, if anything, overstated.
2. From H = 256 the router stops failing at all inside the range searched. A separate run at H = 2048 held precision **1.00 with a library of 9,216 skills**, so the real ceiling for a wide model is far above anything this search can reach.

Reading it: `theta = 0.38` is well under 1, and `theta = 1` is what a bounded quality distribution gives. Under 1 means the gap between the best skill and the rest closes *slower* than the library grows — the signature of a library that keeps its best skills separated as it fills, which is the regime where the ceiling explodes with model width rather than crawling.
